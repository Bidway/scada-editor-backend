Проект, документация и комментарии в коде — на русском. **Коммиты — по-английски**, коротко

## Что это

Серверная часть SCADA: редактор мнемосхем, база каналов, режим мониторинга с записью в ПЛК.
Gradle multi-module (Kotlin DSL), Java 17, Spring Boot.

| Модуль | Порт | Роль |
|---|---|---|
| `gateway` | 8080 | Единственный вход снаружи. Spring Cloud Gateway |
| `auth` | 8081 | Выдача JWT |
| `channel` | 8082 | Узлы и параметры каналов, STOMP WS |
| `editor` | 8083 | Компоненты, шаблоны, наборы значений |
| `runtime` | 8085 | Мониторинг, Kafka, скрипты на GraalVM JS. Своей БД нет |

`script-core` — библиотека без порта и БД: общий технический код скриптов GraalVM (сейчас —
проверка синтаксиса скрипта фоновой задачи; план 2 сервиса `automation` добавит исполнитель).

Одна база `savushkin`, у каждого сервиса своя схема. Миграций нет (`ddl-auto: update`),
данные живут только в дампах.

```powershell
.\gradlew :editor:bootRun                                  # запустить один сервис
.\gradlew :editor:bootRun --args="--server.port=8093"      # второй экземпляр рядом
```

## Что нужно знать до правок

**Тег адресуется только путём канала.** `Барановичи-1.BN1_MCA1.V_ST_1.LINE1V0.ST` — он же
Kafka-key телеметрии, он же `editor.component_property.tag_id`, он же адрес в команде записи.
Числовых id тега на проводе нет ни в одну сторону: у шлюза их два, и наружу публикуется не тот.
Не возвращай числовую адресацию. Следствие: **`runtime` не обращается к `channel` вообще.**

**Подпись JWT проверяет только gateway**, вниз он проставляет `X-User-Id` / `X-Username`, затирая
клиентские значения. У downstream-сервисов `permitAll()` — это осознанно. Изменяющие эндпоинты
читают `@RequestHeader("X-Username")` и токен не разбирают.

**Изменения данных в `channel` идут через Command Pattern**, а не прямым вызовом репозитория:
`commandManager.execute(new XxxCommand(...))` пишет `command_log` со снимком для отмены. Как
добавить команду и undo — `docs/COMMAND_PATTERN.md`.

**В `editor` Command Pattern снят (17.08.2026, `scada-r28`).** История и отмена там — версии
документов: `document_version` хранит снимок, отмена это восстановление версии, дописывающее
историю новой записью, а не отмотка её назад. Ни `command_log`, ни `/api/editor/undo` в
`editor` больше нет — не воскрешай их. Уже принятое исключение с разбором — удаление
компонента по отсутствию в `PUT` (`scada-g39`).

**Command Pattern остался в `channel`** и снимать его оттуда не надо: `/api/channel/undo`
живой, фронт им пользуется. Типы `Command`, `CommandResult`, `UndoHandler` лежат в
`com.example.channel.command` рядом с реализациями — отдельного модуля `shared` больше нет
(`scada-o1z`). `CommandManager`, `CommandLog` и `CommandLogRepository` привязаны к схеме БД
сервиса и лежат там же, в `channel`.

**Логика поделена между бэком и фронтом по правилу «пишет объект или общее состояние — бэк;
только рисует — фронт».** На бэке (`runtime`, GraalVM) исполняются `scripts.script` по `ACTION`
с фронта и `component_property.on_change` по смене тега; на фронте — `component_event.script` и
`binding.script`. Разбор по шагам — `docs/RUNTIME_EXECUTION_CYCLE.md`.

**Каталоги `bin/` появляются при сборке из Eclipse и содержат устаревшие копии ресурсов.**
При поиске исключай `build/` и `bin/`, иначе найдёшь не тот `application.yml`.

**`docker compose up --build` не пересобирает Java-код.** Все Dockerfile'ы делают
`COPY build/libs/*.jar`, то есть берут готовый jar с хоста: без `bootJar` в образ молча уедет
прошлая сборка.

## Документация

Справочник в `docs/` — **он в `.gitignore`, живёт только на этой машине**. Заглядывай туда перед
нетривиальными правками, это быстрее, чем реконструировать по коду.

| Вопрос | Файл |
|---|---|
| Долги и известные неточности | beads: `bd ready`, `bd list` (см. ниже) |
| Схема системы, порты, стек | `docs/ARCHITECTURE.md` |
| Все REST-эндпоинты и WebSocket | `docs/API.md` |
| Таблицы и колонки | `docs/DATA_MODEL.md` |
| Команды, журнал изменений, undo | `docs/COMMAND_PATTERN.md` |
| Полный цикл «клик → ПЛК → экран» | `docs/RUNTIME_EXECUTION_CYCLE.md` |
| Устройство сервиса, его API и грабли | `docs/modules/<сервис>.md` |
| Запуск, переменные, чеклист эндпоинта | `docs/operations/DEVELOPMENT.md` |
| Контракт для фронта и для шлюза | `docs/integration/` |

Правило поддержки: **правка кода задевает один файл документации.** Эндпоинт → `API.md` + файл
модуля; колонка → `DATA_MODEL.md` + файл модуля; формат на проводе → файл модуля + `integration/`
того, кто его читает. Дату актуальности — в шапку, причину — рядом с фактом.

**Заметил расхождение кода с документацией, мёртвый код или отложенное решение — не исправляй
молча по ходу чужой задачи, а заведи задачу в beads: `bd create`** (где, в чём суть, чем грозит,
что сделать). Сделанное закрывай `bd close --reason`, а не удаляй: видно, что уже разбирали.

## Git: ветки и коммиты

**Одна долгоживущая ветка — `main`**, она же дефолтная на GitHub. Работа идёт в коротких
ветках, которые вливаются в `main` и удаляются:

```powershell
git switch -c feat/recipe-export     # feat/ — новая функциональность
git switch -c fix/ws-reconnect       # fix/  — починка
git switch -c docs/api-contract      # docs/ — только документация
```

**Сообщения коммитов — по-английски, коротко, в повелительном наклонении**, до ~50 символов,
без точки в конце. Тело — только если без него непонятно «зачем».

```
Add recipe storage and CRUD
Fail fast on default JWT secret in prod
perf(runtime): move onChange off consumer thread
fix(security): route all external traffic through gateway
```

Префикс `тип(модуль):` необязателен, но уместен для `fix`/`perf`/`docs` в конкретном сервисе.

**Атрибуции ИИ в коммитах не должно быть** — ни `Co-authored-by`, ни ссылок на сессии.
Настроено в `~/.claude/settings.json` (`attribution`), руками дописывать не нужно.

История переписана 10.08.2026: ветки `dev` и `microservice` удалены, их содержимое стало
`main`. Монолит до разделения на сервисы сохранён тегами `archive/monolith-main` и
`archive/monolith-dev` — там же остались исходные русские сообщения тех коммитов.

## Задачи и долги — в beads, не в файле

Трекер — **beads** (`bd`), локальная база Dolt в `.beads/`. Это **не** GitHub Issues: наружу
ничего не уходит. Префикс задач — `scada-`, id вида `scada-3fd`.

```powershell
bd ready                          # что можно делать сейчас (незаблокированное)
bd list                           # все задачи
bd show scada-3fd                 # полный текст задачи
bd create "Название" -t task -p 2 -d "..."   # завести (-p 0..4, 0 — высший)
bd update scada-3fd --claim       # взять в работу
bd note scada-3fd "..."           # дописать по ходу
bd close scada-3fd --reason "..." # закрыть
```

`docs/TODO.md` перенесён сюда 10.08.2026 и больше не ведётся.

**Голый id в тексте для человека не читается.** Упоминаешь задачу в ответе, в отчёте, в
сообщении коммита, в журнале прогона — сразу подписывай в скобках, о чём она, тремя-четырьмя
словами:

```
scada-4yy (wrap() в runtime)          не «сделал scada-4yy»
scada-w51 (trim имён с двух сторон)
scada-95o (UNIQUE в БД)
```

Подпись — краткая суть, а не заголовок задачи целиком. В командах `bd` и в ссылках внутри
задач id, разумеется, остаётся голым.

Грабли:

- **Базы Dolt в git нет.** `.beads/embeddeddolt/` в `.gitignore`, в репозитории лежит только
  конфиг. Задачи живут на этой машине — резервная копия делается `bd backup`.
- **`bd init` коммитит сам, без спроса.** Повторный `bd init` или `bd setup claude` перепишет
  этот раздел англоязычной заготовкой — не запускай без нужды.
- Формулировка задачи — та же, что была в `TODO.md`: где, в чём суть, чем грозит, что сделать.
  Задача без «где» через месяц непроверяема.
