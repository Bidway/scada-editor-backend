# Разбор легаси-проекта BN1_MCA1 (.mpr/.cdbx)

Разбор бинарного `.mpr` (проектный файл старого, до-Java редактора мнемосхем) и `.cdbx`
(XML-база каналов того же легаси-стенда) — для миграции `BN1_MCA1` в текущий `editor`.
Разбор в `docs/learning/` не идёт: `docs/` — про этот код, а не про чужой формат.

## Зависимость от исходников (их в репозитории нет)

Скрипты читают `docs/oldversion/BN1_MCA1 NEW.mpr` и `docs/oldversion/BN1 MCA1 NEW.cdbx` —
эти два файла лежат только на исходной машине (`docs/` в `.gitignore`). Без них скрипты не
запустить заново — но результат разбора уже лежит в `output/` и от исходников не зависит.

## Формат `.mpr`

Бинарный поток в духе Delphi VCL `TReader`/`TWriter`: байт-тег типа значения (`String`/`Ident` —
1-байтная длина; `LString`/`UTF8String` — 4-байтная; `Int8`/`Int16`/`Int32`; `WString` — UTF-16LE
с 4-байтной длиной; и т.д.), без имён свойств — схема записи позиционная и меняется по типу
параметра (дискретный/аналоговый). `decode_mpr.py` разбирает её последовательно и стопорится,
как только встречает незнакомую форму записи (сейчас — на аналоговых параметрах с доп. полями
диапазона) — `mpr_decoded.txt` содержит только то, что успело разобраться (~478 КБ из 1.4 МБ).

Более надёжный путь — `object_channel_map.json`/`object_channel_scripts.json`: они не требуют
полного понимания схемы записи, а ищут в бинаре свойство/объект/скрипт от известного якоря
(числовой id канала из `.cdbx`, он же уникален и легко находится как 4 байта LE).

## Скрипты (запускать из корня репозитория)

1. `decode_mpr.py` — черновой последовательный разбор `.mpr` → `output/mpr_decoded.txt`.
2. `link_channels.py` — подписывает найденные в `.mpr` числа-id именами каналов из `.cdbx`
   → `output/mpr_decoded_linked.txt`.
3. `build_object_map.py` — полная таблица «объект → свойство → канал» прямо из `.cdbx`
   (надёжный источник, 100% покрытие) + отметка, какие id реально встречаются в `.mpr`
   → `output/object_channel_map.json` / `.txt`.
4. `extract_scripts.py` — для каждого свойства из `object_channel_map.json` ищет в `.mpr`
   ближайший скрипт отрисовки состояния (эвристика: якорь по числу id канала, скан назад
   на паскаль-маркеры `self.`/`SelFrame`/`end;`) → `output/object_channel_scripts.json` / `.txt`,
   `output/scripts_grouped.txt` (те же скрипты, сгруппированные по типу параметра).

`output/mpr_strings.txt`, `shapes.txt`, `families.txt`, `summary.txt` — вспомогательные
однострочные выгрузки того же разбора, отдельных скриптов под них нет.

## Что в `output/`

- `object_channel_map.json` / `.txt` — 367 объектов, 2665 свойств/каналов, самый полный и
  надёжный результат (источник — `.cdbx`, не бинарник).
- `object_channel_scripts.json` / `.txt`, `scripts_grouped.txt` — то же плюс скрипт отрисовки
  состояния там, где он нашёлся (1149 из 2665 свойств).
- `mpr_decoded.txt`, `mpr_decoded_linked.txt`, `mpr_strings.txt` — сырой разбор `.mpr`,
  полезны как справочный материал, но избыточны относительно `object_channel_*`.
- `shapes.txt` — 367 объектов сгруппированы в 22 уникальных набора свойств (типа компонента).
- `families.txt`, `summary.txt` — сводки по семействам объектов и по покрытию скриптами.
