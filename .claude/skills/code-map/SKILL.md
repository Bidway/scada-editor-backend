# code-map

Строит и поддерживает актуальной карту кодовой базы: `docs/learning/map/MAP.md`,
`docs/learning/map/CALLS.md`, `docs/learning/map/FLOWS.md`,
`docs/learning/map/modules/{gateway,auth,channel,editor,runtime}.md`.

## Перед началом

Прочитай `.claude/learn/METHOD.md`, раздел «Источник правды» — там правило,
какие файлы считаются фактами о коде (исходники), а какие нет (`docs/`,
`README.md`, `CLAUDE.md`), и как поступать с расхождением комментария и кода.
Действуй по нему на протяжении всего скила.

Проверь, существует ли `docs/learning/map/MAP.md`:

- нет — карты ещё не было, иди в раздел «Полный проход»;
- есть — карта уже строилась, иди в раздел «Обновление».

## Полный проход

Раздай пять субагентов, по одному на модуль: `gateway`, `auth`, `channel`,
`editor`, `runtime`. Каждому — один и тот же промпт с подставленным именем модуля:

> Прочитай все `.java` в `<модуль>/src/main`. Не открывай `docs/`, `README`,
> `CLAUDE.md`, `build/`, `bin/`, `src/test`. Верни три блока:
>
> 1. СТРУКТУРА: по каждому пакету — назначение одной фразой и список классов,
>    каждый с ролью в одну строку. Для классов, где есть фоновое исполнение,
>    разделяемое состояние или блокировки, добавь строку «поток: …».
> 2. ВЫЗОВЫ: по каждому классу — кого он вызывает (только классы этого проекта)
>    и кто вызывает его.
> 3. ВНЕШНИЕ ГРАНИЦЫ: HTTP-клиенты с URL, Kafka-топики с именами, WS-эндпоинты,
>    таблицы БД. Это точки стыка с другими модулями.

Собери результаты:

- `modules/<модуль>.md` — из блока СТРУКТУРА каждого агента.
- `CALLS.md` — из блоков ВЫЗОВЫ, плюс межмодульные связи, восстановленные по
  блокам ВНЕШНИЕ ГРАНИЦЫ: совпадающий Kafka-топик или URL связывает два модуля.
- `FLOWS.md` — отдельным проходом поверх собранного. Начни от внешних входов
  (Kafka-консьюмеры, REST-контроллеры, WS-обработчики) и проследи каждый до
  выхода. Сценарий получает имя по тому, что видит пользователь системы, а не по
  имени класса: «телеметрия ПЛК → экран», а не «TagKafkaConsumer flow».

В `MAP.md` запиши шапку и оглавление:

```
snapshot: <вывод git rev-parse HEAD>
updated:  <сегодняшняя дата ДД.ММ.ГГГГ>
dirty:    <да, если git status --porcelain непуст, иначе нет>
```

### Формат слоёв (обязателен — от него зависят другие скилы)

- **`modules/<модуль>.md`** — каждый пакет отдельным заголовком второго уровня
  вида `## com.example.<модуль>.<пакет>`, например `## com.example.runtime.stream`.
  Под заголовком — назначение пакета одной фразой и список классов пакета с
  ролью в одну строку и, где применимо, строкой «поток: …».
- **`CALLS.md`** — запись на класс: простое имя класса (без пакета) заголовком,
  под ним ровно две строки:

  ```
  <ПростоеИмяКласса>
    ← вызывается: <классы/файлы, которые его вызывают>
    → вызывает: <классы, которые вызывает он>
  ```

- **`FLOWS.md`** — каждый сценарий начинается строкой `## Сценарий: <название>`
  и заканчивается строкой `узлы: [<модуль>.md#<пакет>] [<модуль>.md#<пакет>] …` —
  перечнем пакетов-узлов, через которые проходит сценарий, в порядке прохождения.

## Обновление

Возьми `snapshot` из шапки `MAP.md` и собери список затронутых файлов:

```bash
git diff <snapshot>..HEAD --name-only -- '*.java'
git status --porcelain -- '*.java'
```

Если оба списка пусты — скажи, что карта актуальна, и остановись. Ничего не
переписывай.

Иначе по каждому затронутому файлу:

| Что случилось | Что переписать |
|---|---|
| Изменён | раздел его пакета в `modules/<модуль>.md`; все записи в `CALLS.md`, где встречается имя класса |
| Добавлен | то же + проверить, не появился ли новый пакет |
| Удалён или переименован | вычистить записи во всех трёх слоях |
| Упоминается в `FLOWS.md` | пометить сценарий строкой `СТАТУС: требует проверки` и перечитать его целиком |

Порог: если затронуто больше трети `.java`-файлов модуля — пересобери модуль с
нуля по инструкции «Полный проход» для одного этого модуля. Инкремент дешевле не
выйдет.

В конце обнови `snapshot`, `updated` и `dirty` в шапке `MAP.md`.

## Расхождения с документацией

Если по ходу разбора видно, что `docs/ARCHITECTURE.md` или другой файл
документации противоречит коду, не исправляй документацию и не подстраивай под
неё карту — карта пишется только по коду. Вместо этого заведи задачу:

```bash
bd create "<где> — <в чём расхождение>" -t task -p 3 -d "…"
```
