# От симптома к причине

## Перед началом

Прочитай `.claude/learn/METHOD.md` и держись его на протяжении всего расследования.

Это не отладка боевого инцидента. Цель — чтобы пользователь понял механизм, а не
чтобы починить как можно быстрее. Быстрый патч без понимания здесь считается
провалом, а не успехом.

## Порядок

1. **Переформулируй симптом в проверяемое утверждение и покажи пользователю:**
   «то есть значение уходит из runtime, но до экрана не доходит — так?». Неверно
   понятый симптом уводит расследование целиком, и это самая дорогая ошибка здесь.

2. **Определи по `docs/learning/map/FLOWS.md`, в каком сценарии живёт симптом**, и
   сузь до отрезка маршрута. Карты нет — скажи и предложи вызвать `code-map`, сам
   не вызывай.

3. **Прежде чем читать код, спроси, где по мнению пользователя теряется и почему он
   так думает** (`METHOD.md`, раздел «Сначала вопрос»). Его гипотеза — рабочий
   материал: она показывает, какой части картины не хватает, и объяснение надо
   строить оттуда.

4. **Проверяй гипотезы по одной, от самой дешёвой.** По каждой говори вслух, что
   именно смотришь и что увидел. Отвергнутая гипотеза — тоже результат, её надо
   назвать: половина понимания системы состоит из знания, где причина НЕ лежит.

5. **Дойдя до причины, покажи конкретную строку** и объясни механизм по схеме из
   `METHOD.md`.

6. **Выдай ответ четырьмя блоками ровно с такими заголовками:**

   ```
   ## Симптом
   ## Что проверено
   ## Причина
   ## Как убедиться
   ```

   Заголовки обязаны быть дословно такими: `code-study` разбирает по ним твой ответ.

В блоке «Как убедиться» дай конкретную проверку: какой лог включить, куда поставить
брейкпоинт, какой запрос выполнить. Не «можно подебажить».

## Если причина не нашлась

Код не подтверждает ни одной гипотезы — так и скажи. Правдоподобная догадка,
выданная за причину, хуже честного «не нашёл»: пользователь запомнит неверный
механизм и будет строить на нём дальше.

## Найденное — в beads

Расследование вскрыло настоящий баг или долг — заведи задачу:

```powershell
bd create "<где> — <в чём суть>" -t bug -p 2 -d "где, в чём суть, чем грозит, что сделать"
```

Упоминая её дальше, подписывай в скобках, о чём она. Не чини по ходу: задача была
разобраться.

Сам в `KNOWN.md` и `JOURNAL.md` не пиши — их ведёт только `code-study`.
Если карта разошлась с кодом — поправь узел на месте и скажи об этом.
