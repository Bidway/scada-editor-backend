# Запуск демо редактора на сервере — по шагам

Сервер: Ubuntu/Debian. Старый клон репозитория лежит в `~/scada-editor-ms`.
Везде, где встречается `203.0.113.10`, подставь IP сервера, а вместо `ПАРОЛЬ_БАЗЫ` —
придуманный пароль (один и тот же в шагах 5 и 6).

---

## Шаг 1. Перейти на ветку (сервер)

История репозитория переписывалась, поэтому `git pull` на старой ветке **не делать**.

```bash
cd ~/scada-editor-ms
git status                         # если есть свои правки: git stash
git fetch origin
git switch demo/editor-standalone
git log --oneline -1               # последний коммит ветки
```

## Шаг 2. Скачать архив с программой (сервер)

Готовые jar и фронт лежат не в git (jar редактора больше 100 МБ), а в релизе на GitHub:
https://github.com/Bidway/scada-editor-backend/releases/tag/demo-editor-2026-09-25

```bash
wget -O /tmp/scada-demo.tar.gz   https://github.com/Bidway/scada-editor-backend/releases/download/demo-editor-2026-09-25/scada-demo.tar.gz
ls -lh /tmp/scada-demo.tar.gz      # около 220 МБ
```

Нет `wget` — то же через `curl -L -o /tmp/scada-demo.tar.gz <та же ссылка>`.

## Шаг 3. Проверить и поставить нужные программы (сервер)

```bash
java -version      # нужна 17 или новее
node -v            # нужна v20 или новее
psql --version
nginx -v
```

Чего нет — поставить:

```bash
sudo apt update
sudo apt install -y openjdk-17-jre-headless postgresql nginx openssl

# Node.js 20 — только если node нет или версия ниже 20:
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
```

## Шаг 4. Распаковать в /opt/scada-demo

```bash
sudo useradd --system --home /opt/scada-demo --shell /usr/sbin/nologin scada
sudo mkdir -p /opt/scada-demo/data/recipes
sudo tar -xzf /tmp/scada-demo.tar.gz -C /opt/scada-demo
sudo chown -R scada:scada /opt/scada-demo
ls /opt/scada-demo                 # auth.jar editor.jar gateway.jar frontend server README.md data
```

## Шаг 5. Создать базу

```bash
sudo systemctl enable --now postgresql
sudo -u postgres psql -c "CREATE USER scada WITH PASSWORD 'ПАРОЛЬ_БАЗЫ';"
sudo -u postgres psql -c "CREATE DATABASE savushkin OWNER scada;"
```

Таблицы создавать не нужно — сервисы создадут их сами.

## Шаг 6. Файл настроек

```bash
cd /opt/scada-demo
sudo cp server/scada.env.example scada.env
sudo sed -i "s/^DB_PASSWORD=.*/DB_PASSWORD=ПАРОЛЬ_БАЗЫ/" scada.env
sudo sed -i "s/^JWT_SECRET=.*/JWT_SECRET=$(openssl rand -hex 32)/" scada.env
sudo chown scada:scada scada.env
sudo chmod 600 scada.env
sudo grep -E "DB_PASSWORD|JWT_SECRET" scada.env     # CHANGE_ME остаться не должно
```

## Шаг 7. Запустить сервисы

```bash
sudo cp /opt/scada-demo/server/systemd/*.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now scada-auth scada-editor
sleep 40
sudo systemctl enable --now scada-gateway scada-frontend
sleep 20
systemctl --no-pager status scada-auth scada-editor scada-gateway scada-frontend | grep -E "●|Active"
```

У всех четырёх должно быть `active (running)`. Если какой-то `failed`:

```bash
sudo journalctl -u scada-editor -n 100 --no-pager     # вместо editor — имя упавшего
```

## Шаг 8. HTTPS через nginx

Без HTTPS вход не работает: браузер не сохраняет cookie входа по `http://`.

```bash
IP=203.0.113.10
sudo mkdir -p /etc/ssl/scada-demo
sudo openssl req -x509 -nodes -newkey rsa:2048 -days 825 \
  -keyout /etc/ssl/scada-demo/key.pem -out /etc/ssl/scada-demo/cert.pem \
  -subj "/CN=$IP" -addext "subjectAltName=IP:$IP"

sudo rm -f /etc/nginx/sites-enabled/default
sudo cp /opt/scada-demo/server/nginx/scada-demo.conf /etc/nginx/sites-available/
sudo ln -sf /etc/nginx/sites-available/scada-demo.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

Если включён файрвол (`sudo ufw status` показывает `active`):

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
```

## Шаг 9. Открыть в браузере

1. `https://203.0.113.10`
2. Предупреждение о сертификате → «Дополнительно» → «Перейти на сайт».
3. «Зарегистрироваться» — каждый тестер заводит себе логин сам.
4. В меню — «Редактор схем» → кнопка «Проект» → создать проект → создать схему.
5. Элемент: клик в палитре, затем клик по холсту. Состояния — справа, вкладка
   «Состояния». Сохранить — кнопка с дискетой.

Пункты меню «Монитор», «База каналов», «Автоматизация», «Логирование» в демо не работают —
так и задумано.

## Потом пригодится

```bash
# логи (Ctrl+C — выход)
sudo journalctl -u scada-editor -f

# перезапустить всё
sudo systemctl restart scada-auth scada-editor scada-gateway scada-frontend

# остановить всё
sudo systemctl stop scada-frontend scada-gateway scada-editor scada-auth

# поставить новую сборку (новый архив уже в /tmp)
sudo systemctl stop scada-frontend scada-gateway scada-editor scada-auth
sudo rm -rf /opt/scada-demo/frontend
sudo tar -xzf /tmp/scada-demo.tar.gz -C /opt/scada-demo
sudo chown -R scada:scada /opt/scada-demo
sudo systemctl start scada-auth scada-editor && sleep 40 && sudo systemctl start scada-gateway scada-frontend

# стереть все данные и начать с чистой базы
sudo systemctl stop scada-frontend scada-gateway scada-editor scada-auth
sudo -u postgres psql -c "DROP DATABASE savushkin;" -c "CREATE DATABASE savushkin OWNER scada;"
sudo systemctl start scada-auth scada-editor && sleep 40 && sudo systemctl start scada-gateway scada-frontend
```

| Симптом | Причина |
|---|---|
| `password authentication failed` в логе | пароль в `scada.env` не совпадает с шагом 5 |
| После регистрации снова выкидывает на вход | зашли по `http://`, а не `https://` |
| `502 Bad Gateway` | не запущен `scada-frontend` |
| Сервис падает с `OutOfMemoryError` | поднять `-Xmx` в `/etc/systemd/system/scada-*.service`, затем `sudo systemctl daemon-reload` и `restart` |
